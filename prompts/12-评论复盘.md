# 场景 12 · 评论复盘（跑运营）

**何时用**：上架 60 天评论有积累后，验证主打卖点哪些被真实买账、哪些是自嗨。

**提示词**（【】内替换为实际值；【数据MCP】= 环境中已接入的数据源 MCP）：

```
我的产品【ASIN】上架【60】天了，评论积累了一些。请用【数据MCP】 拉取我的评论做一轮复盘，同时拉竞品【ASIN】的评论做对比：
① 我的评论盘点：总量、星级分布、增长趋势
② 卖点验证：我在 Listing 里主打的那几个卖点，逐个对照评论——哪些被买家真实提及和称赞（验证成功，加大投入）、哪些零提及（自嗨卖点，考虑换）、有没有买家在夸但我的 Listing 没写的（新卖点素材）
③ 痛点预警：我的差评按"产品缺陷/预期落差/物流服务/使用门槛"归因——产品类的反复抱怨是改进信号；预期落差类说明 Listing 过度承诺，要改的是文案不是产品
④ 竞品对比：竞品好评在夸什么我没做到的（差距）、竞品差评在骂什么我已经做到的（差异化验证，值得写进文案）
数据标注来源和评论总数。最后输出三张清单：Listing 迭代清单（该加的卖点/该降的预期）、产品改进清单（真实缺陷，反馈给供应链）、评论运营清单（值得跟进互动的好评、值得引导买家关注的功能）。输出为评论复盘报表（星级分布+卖点验证表+归因图）。
```
